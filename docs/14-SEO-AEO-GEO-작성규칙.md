# 14. SEO · AEO · GEO 작성 규칙

목표: 구글 검색 상위노출과 동시에 **제미나이·ChatGPT·클로드·퍼플렉시티가 답변에서 인용**하게 만드는 것.

## 0. 먼저 알아야 할 것 — 이건 양날의 검입니다

**AI가 답을 완결해 주면 사용자가 클릭하지 않습니다.** 인용은 되는데 트래픽은 안 오는 상황이 실제로 생기고, 애드센스 수익은 클릭·노출 기반이라 직접적으로 상충합니다.

그럼에도 해야 하는 이유는 셋입니다.
- AI 답변의 **인용 링크**를 통한 유입이 존재하고, 이 유입은 의도가 명확해 체류시간이 깁니다
- GEO를 위한 구조(직접 답변, 숫자, 출처, 스키마)는 **구글 SEO에도 그대로 유리**합니다
- 검색 트래픽이 AI로 이동하는 흐름에서 아무것도 안 하면 나중에 자리가 없습니다

전략은 **"AI가 요약은 하되 세부는 원문을 봐야 하도록"** 쓰는 것입니다. 결론은 앞에 주되, 계산 예시·조건 분기·서류 목록 같은 세부는 본문에만 둡니다.

## 1. 왜 구조가 중요한가 — RAG 메커니즘

생성형 검색은 페이지 전체를 읽지 않습니다. 문서를 **청크(문단 단위)로 쪼개 벡터로 임베딩**하고, 질문과 의미가 가장 가까운 청크를 꺼내 답을 만든 뒤 그 청크의 출처를 인용합니다.

여기서 나오는 결론이 결정적입니다.

> **각 섹션이 그 자체로 완결된 답이어야 하고, 숫자와 출처가 그 섹션 안에 있어야 합니다.**

제 초기 글은 출처를 전부 글 하단에 몰아놨습니다. 그 청크만 뽑히면 근거가 없어서 인용 가치가 떨어집니다. **출처를 각 섹션으로 분산**해야 합니다.

## 2. 측정된 효과 (프린스턴 GEO 연구)

| 기법 | 가시성 증가 |
|---|---|
| **인용문 추가** | **+27.8%** |
| **통계·수치 추가** | **+25.9%** |
| **출처 인용** | **+24.9%** |
| 조합 최대 | 최대 +40% |

키워드 밀도나 글자 수는 유의미한 효과가 없었습니다. **인용·통계·출처 세 가지가 핵심입니다.**

스키마 쪽 데이터도 있습니다. **속성이 풍부한 스키마는 인용률 61.7%**인데, **빈약하거나 본문과 어긋나는 스키마는 아예 없는 것보다 나쁩니다.**

## 3. 작성 규칙

### 3-1. 도입부 — 직접 답변 (AEO 핵심)

```
결론부터: [질문에 대한 한 문장 답. 숫자 포함]
```

- 첫 40단어 안에 답이 끝나야 합니다
- 질문형 제목이면 첫 문장이 그 답이어야 합니다
- 이 블록에 `speakable` 스키마가 걸려 있습니다 (음성 검색 대응)

### 3-2. 각 H2 섹션 = 독립된 답변 단위

한 섹션만 떼어내도 말이 되어야 합니다.

- 섹션 첫 문장에 그 섹션의 결론
- **그 섹션에서 쓰는 숫자의 출처를 그 섹션 안에 표기**
  - 나쁨: "상한액은 68,100원입니다" (출처는 글 맨 아래)
  - 좋음: "상한액은 68,100원입니다(고용노동부 2026년 고시)"
- 대명사로 앞 섹션을 참조하지 않기 — 청크 단독으로 읽히므로 "이것", "앞서 말한"은 의미가 사라집니다

### 3-3. 세 가지 필수 요소

| 요소 | 넣는 법 |
|---|---|
| **통계·수치** | 섹션마다 최소 1개. 기준일과 함께 |
| **출처** | 기관명을 본문 안에. "고용보험(ei.go.kr)", "국세청 고시" |
| **인용** | 법령·공식 문구를 직접 인용. `<blockquote>` 또는 "○○법 제○조는 …라고 규정합니다" |

### 3-4. 표와 번호 목록

- **표**는 AI 인용률이 가장 높은 형식입니다. 섹션당 1개 이상
- **번호 목록**은 HowTo 스키마로 자동 변환됩니다 (3단계 이상일 때)
- 표에는 반드시 헤더 행을 두고, 셀에 단위를 명시

### 3-5. FAQ

- 실제 검색되는 질문 형태로 (연관검색어에서 가져오기)
- 답변은 **첫 문장에서 완결**. 부연은 그다음
- FAQPage 스키마로 자동 변환되며, **본문과 한 글자도 다르면 안 됩니다**

## 4. 구조화 데이터

`md2tistory.py`가 `@graph`로 자동 생성합니다.

| 타입 | 언제 |
|---|---|
| **Article** | 항상. headline, description, datePublished/Modified, author, publisher, articleSection, keywords, speakable |
| **FAQPage** | FAQ 섹션이 있을 때 |
| **HowTo** | 번호 목록이 3단계 이상일 때 |

**발행 전 반드시 `SITE` 상수를 실제 값으로 바꾸세요.**
```python
SITE = {"name": "블로그명", "url": "https://주소",
        "author": "필자명", "authorUrl": "https://소개페이지"}
```

필자명과 소개 페이지가 비어 있으면 E-E-A-T 신호가 없습니다. **소개 페이지를 하나 만들고 경력·연락처를 적어두세요.** 금융·정책 같은 YMYL 주제에서는 이게 순위와 인용 모두에 영향을 줍니다.

## 5. llms.txt

```bash
python3 tools/gen_llms_txt.py --site "블로그명" --url https://주소 --full
```

`web/llms.txt` — 핵심 문서 목록 + 한 줄 요약
`web/llms-full.txt` — 전문

사이트 루트(`/llms.txt`)에 올립니다. **티스토리는 루트 파일 업로드가 안 되므로 워드프레스나 자체 도메인에서만 가능합니다.** 티스토리는 스키마와 본문 구조로 대응합니다.

## 6. 발행 후 확인

인용 여부는 검색해 보는 수밖에 없습니다.

1. 타깃 질문을 **ChatGPT · 제미나이 · 클로드 · 퍼플렉시티**에 그대로 물어보기
2. 내 글이 인용되는지, 경쟁 글이 인용되는지 확인
3. 서치콘솔에서 **AI Overview 노출** 추이 확인
4. 애널리틱스에서 chatgpt.com, perplexity.ai, gemini.google.com 리퍼러 확인

인용이 안 되면 대개 원인이 셋입니다 — 섹션이 독립적이지 않거나, 숫자·출처가 청크 안에 없거나, 스키마가 본문과 어긋납니다.

## 7. 체크리스트

- [ ] 첫 40단어 안에 질문의 답
- [ ] 각 H2가 단독으로 읽히는가 (대명사로 앞 섹션 참조 없음)
- [ ] 섹션마다 수치 1개 이상 + **그 섹션 안에 출처**
- [ ] 표 1개 이상, 헤더 행과 단위 명시
- [ ] 법령·공식 문구 직접 인용 1개 이상
- [ ] FAQ 3개 이상, 본문과 스키마 내용 일치
- [ ] `SITE` 상수를 실제 값으로 교체
- [ ] 필자 소개 페이지 존재
- [ ] 제목에 연도 표기
- [ ] 대표 이미지 1200px 이상

알파남(@alphamale__1212) 영상 "구글 네이버 상위노출 4가지 SEO GEO

배치는 이미 본 문서와 일치. 아래는 새로 규칙으로 못박은 것.

### 8-1. 제목 공식 (가장 많이 지적된 항목)

> 메인 키워드 + 서브 키워드 + 마무리 문구

- **후킹형 제목 금지.** 유튜브식 제목("삼계탕 말고도 많습니다")은
  검색 유입을 못 만듦. 대시(—)로 이어 붙인 부제도 같은 문제
- **연관검색어를 제목에 넣는다.** 발행 전 대상 키워드를 구글·네이버에
  직접 검색해 자동완성·연관검색어를 확인하고, 실제 사용자가 쓰는
  표현을 조합. 검색량 API 수치만으로 제목을 짓지 않음
- **마무리는 "총정리 / 방법 / 조건 / 얼마"** 같은 검색되는 말로 닫는다

| 나쁨 | 좋음 |
|---|---|
| 2026 말복은 8월 14일 — 삼계탕 말고도 많습니다 | 2026 말복 날짜 8월 14일, 초복 중복 말복 음식과 삼계탕 가격 총정리 |
| 에어컨 청소 비용 알아보기 | 에어컨 청소비용 집주인 세입자 부담 평균 얼마 총정리 |

### 8-2. 쉬운 말 — 초등학생·할머니 기준

영상에서 가장 강조한 대목. **전문용어를 쓰면 그 자리에서 독자를 잃는다.**

- 한자어·법률용어·업계용어는 처음 나올 때 **바로 옆에서 풀어 쓴다**
  - 나쁨: "대항력은 전입신고 다음 날 0시에 생깁니다"
  - 좋음: "대항력은 집주인이 바뀌어도 계약 기간까지 계속 살 수 있는
    권리입니다. 전입신고 다음 날 0시에 생깁니다"
- 모호한 표현 금지. **구체적인 숫자와 이유를 붙인다**
  - 나쁨: "구석구석 꼼꼼하게 청소하는 게 좋습니다"
  - 좋음: "필터·냉각핀·송풍구의 먼지와 곰팡이를 6개월에 한 번 제거하세요"
- 표에 **가격·시간·횟수**가 없으면 그 표는 정보가 아님

### 8-3. 분량 — 늘리지 않는다

**500자로 끝날 내용이면 500자만 쓴다.** 글자수·사진수를 채우려고
서론을 늘리거나 배경 설명을 붙이는 것은 네이버식 구식 최적화이고,
지금은 오히려 감점 요인. 독자가 궁금해하지 않는 섹션은 통째로 삭제.

- 판단 기준: 그 섹션이 없으면 독자가 검색을 한 번 더 해야 하는가?
  아니라면 뺀다
- 단답형 글(쿠팡 고객센터 등)은 1,200자면 충분

### 8-4. 발행 형식 — 순수 텍스트

티스토리 앱 기본모드와 네이버 스마트에디터는 **마크다운을 해석하지
않는다.** `##`, `**`, `|표|`가 그대로 화면에 찍힘.

- `tools/md2text.py`로 변환한 `content/articles/text/*.txt`를 붙여넣는다
- 표는 텍스트 줄로 풀려 나옴 (모바일에서 가로로 밀리지 않도록)
- 붙여넣은 뒤 소제목 줄만 잡아 에디터의 **소제목(제목2)** 스타일 지정
- 광고는 본문에 넣지 않는다. 티스토리 **관리 → 수익 → 애드센스 관리**의
  자동광고(본문 상단·중간·하단)로 처리 → docs/08

쇼츠)와 링크 프리뷰 카드 활용은 트래픽 확장 전술이라 별도 채널 확장
