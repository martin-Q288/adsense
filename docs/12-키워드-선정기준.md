# 12. 키워드 선정 기준

기준이 두 겹입니다. **엔진이 자동으로 뽑는 기준**과, **제가 실제로 원고를 쓸 때 적용하는 기준**입니다. 8/2에 이 둘이 어긋나서 큐를 따르지 않았으므로, 양쪽을 다 적습니다.

---

## 1. 엔진 자동 선정 (`tools/content_engine.py`)

### 1-1. 점수 공식

```
점수 = 단가티어 × 10
     × 축 가중치
     × 1.25  (고단가 신호어 포함 시)
     × (1 + 0.8 × 시급도)  (시즌·정책 이벤트만)
     + 우선순위 × 2        (시즌·정책 이벤트만)
```

**단가티어 (1~5)** — `keywords/bank.csv`에 시드마다 수동 부여
| 티어 | 예시 |
|---|---|
| 5 | 개인회생, 전세자금대출, 임플란트 비용, 교통사고 합의금 |
| 4 | 종합소득세, 자동차보험, 청년월세 지원 |
| 3 | 국민연금, 여권 발급, 노트북 |
| 2 | 전기요금 절약, 기저귀, 선풍기 |

**축 가중치** — 롱테일일수록 신규 블로그가 먹기 쉽다는 가정
| 축 | 가중치 |
|---|---|
| 원본 (완성형 시드 그대로) | **1.60** |
| 오류/문제해결 | 1.30 |
| 준비물·서류 / 연락처·창구 | 1.25 |
| 자격/조건 | 1.15 |
| 계산/금액, 시청/접속 | 1.10 |
| 방법/절차 | 1.00 |
| 비교/대안 | 0.90 |

**고단가 신호어** (포함 시 ×1.25)
대출·보험·세금·변호사·회생·파산·상속·청약·적금·펀드·ETF·주식·지원금·환급·실비·치료·수수료·이자·연금·퇴직

**시급도** — 이벤트일이 가까울수록 상승. `(30 − 남은일수) ÷ 30`

### 1-2. 배치 제약

점수만으로는 안 되고 아래 제약이 걸립니다.

- **선점일 이전 배정 금지** — 추석 기차표는 8/13부터만 나옵니다
- **이벤트별 슬롯 예약** — 우선순위 10인 이벤트는 12편을 미리 확보. 점수 경쟁에 맡기면 8월 최대 이벤트가 밀려서 0편이 되는 문제가 실제로 있었습니다
- **하루 한 시드 1편** — 같은 주제 반복 방지
- **하루 한 축 최대 n/3편** — T1(10슬롯)이면 같은 축 3편까지
- **블로그 적합성** — N(네이버)은 단가티어 3 이하 생활밀착만

### 1-3. 완성형 시드 처리

"전세자금대출 거절 사유"처럼 이미 완성된 검색어를 또 8축으로 전개하면 "…거절 사유 고객센터" 같은 게 나옵니다. 그래서 3어절 이상이거나 방법·사유·조건·계산 등으로 끝나면 **원본을 그대로 쓰고** 축 전개는 3개로 제한합니다.

## 2. 엔진의 한계 — 솔직하게

**엔진에는 검색량 데이터가 없습니다.** 단가티어는 제가 손으로 넣은 추정치이고, 검색량은 아예 반영이 안 됩니다. 그래서 8축 전개가 "항공권 최저가 준비물", "골프채 계산 방법" 같은 조합을 뱉습니다. 문법적으로 가능하지만 아무도 검색하지 않습니다.

정확히 말하면 엔진은 **후보 생성기**입니다. 순위를 매기긴 하지만, "이게 실제로 검색되는가"는 판단하지 못합니다.

### 해결됨 — 네이버 검색광고 API 연동 (2026-08-02)

실측 데이터를 붙였습니다. 이제 기계 전개가 아니라 **네이버가 반환한 실제 검색 질의**를 씁니다.

```bash
# 인증 정보는 환경변수로만. 절대 커밋 금지
export NAVER_CUSTOMER_ID=... NAVER_API_KEY=... NAVER_SECRET_KEY=...
python3 tools/naver_keyword.py --from-bank --min 300 -o keywords/volume.csv
python3 tools/rank_keywords.py --max-comp 0.65 -o keywords/ranked.csv
```

- 뱅크 시드 224개 → **연관 키워드 11,948개** 수집 (월검색량·경쟁도·광고수 포함)
- 필터(월 1,000회 이상, 경쟁도 중간 이하) 통과 **1,638개**

**새 점수 공식** (`tools/rank_keywords.py`)
```
점수 = log10(월검색량) × 단가티어 × (1 − 경쟁도)²
```

단가티어는 뱅크 시드와 매칭해 상속하고, 매칭이 안 되면 신호어로 추정합니다.
증권 종목·브랜드명(코스피, KODEX, 삼성전자, 토스 등)은 뉴스·증권사이트에 밀리므로 제외 규칙을 뒀습니다.

### 실측이 뒤집은 것

기존 8축 전개로는 절대 나올 수 없었던 키워드들이 상위를 차지했습니다.

| 키워드 | 월검색량 | 경쟁도 | 광고수 |
|---|---|---|---|
| 청년미래적금 | **1,113,200** | 낮음 | **0** |
| 국민연금 | 250,100 | 낮음 | 2 |
| 근로장려금 | 205,600 | 낮음 | 0 |
| 실업급여계산기 | 107,200 | 낮음 | 2 |
| 국가장학금 | 88,000 | 낮음 | 0 |
| 주민등록등본 인터넷발급 | 40,660 | 낮음 | 1 |
| 부동산양도세계산기 | 13,380 | 낮음 | 0 |

반대로 제가 추정으로 높게 잡았던 것 중 실제로는 경쟁이 극심한 것도 드러났습니다 (전세대출·주담대금리·신용카드추천 모두 경쟁도 높음, 광고 10개).

### 최대 발견 — "계산기" 패턴

상위 30개 중 12개가 계산기 질의입니다. 부동산양도세계산기 · 세금계산기 · 실업급여계산기 · 청약가점계산기 · 퇴직연금계산기 · 월급세금계산기 · 고용보험계산기 · 3.3%계산기 · 신용대출DSR계산기 · 현금증여세계산기 · 세액계산기 · 아파트양도세계산기.

공통점: **검색량 높음 + 단가 높음 + 경쟁도 낮음 + 광고 0~2개.**

경쟁이 낮은 이유는 명확합니다. 글로 답할 수 없는 질의라 정보성 블로그가 잘 안 건드립니다. 사용자는 **실제로 계산되는 도구**를 원합니다.

→ 이 키워드군은 글에 **JavaScript 계산기를 실제로 넣어야** 의도가 충족됩니다. 체류시간도 크게 오릅니다. 다음 작업 우선순위 1번입니다.

## 3. 제가 원고를 쓸 때 적용하는 기준

큐는 참고만 하고, 실제로는 아래 6개를 통과한 것만 씁니다.

| # | 기준 | 확인 방법 |
|---|---|---|
| 1 | **실제로 검색되는 질의인가** | 기계 조합 티가 나면 버림 |
| 2 | **검색량 × 단가** | 둘 다 중간 이상. 하나만 높으면 후순위 |
| 3 | **시의성** | 8월 이벤트·시즌에 걸리는가 |
| 4 | **사실 확인이 가능한가** | YMYL이면 공식 출처(고용보험·홈택스·주택도시기금 등)로 수치 검증 가능해야 함. 안 되면 안 씀 |
| 5 | **내부링크로 물리는가** | 기존 글과 순환 구조를 만드는가. Vignette 수익의 출발점 |
| 6 | **경쟁** | 상위 10개에 블로그 글 3개 미만 |

4번이 가장 강한 필터입니다. **숫자를 확인할 수 없으면 아무리 단가가 높아도 안 씁니다.** 금융·세금·정책은 수치 하나가 틀리면 순위가 아니라 사이트가 위험합니다.

### 8/2에 큐를 안 따른 이유

큐가 내놓은 것: 항공권 최저가 준비물 / 골프채 계산 방법 / 로봇청소기 계산 방법 / 노트북 사용법 / 에어컨 전기요금(8/1에 이미 씀)

기준 1에서 전부 탈락했습니다. 대신 직접 고른 것:

| 글 | 통과한 기준 |
|---|---|
| 전세자금대출 거절 사유 | 검색량 상 + 단가 최상 + 사실확인 가능 + 버팀목/확정일자와 순환 |
| 개인회생 자격조건 | 단가 최상 + 2026 최저생계비 154만원 확인됨 |
| 신용점수 올리는 법 | 검색량 최상 + 위 두 글의 허브 역할 |
| 태풍 대비 | 8월 시의성 (기준 3) |
| 국민연금 조기수령 | 생활밀착(N 적합) + 퇴직금 글과 연결 |
| 로봇청소기 | T2 커머스, 검증 부담 낮음 |

## 4. 정리 (2026-08-02 갱신)

**선정 순서가 바뀌었습니다.** 기계 전개는 보조로 내려가고 실측이 1차 소스가 됩니다.

1. `naver_keyword.py` — 뱅크 시드로 네이버 연관 키워드 + 실측 검색량 수집
2. `rank_keywords.py` — `log10(검색량) × 단가티어 × (1−경쟁도)²` 로 정렬
3. 시즌·정책 이벤트는 `content_engine.py`가 선점일에 맞춰 별도 예약
4. 최종 판단은 사람이 — **사실 확인 가능성**이 가장 강한 필터

| 단계 | 도구 | 산출 |
|---|---|---|
| 수집 | naver_keyword.py | volume.csv (11,948개) |
| 정렬 | rank_keywords.py | ranked.csv (1,638개) |
| 일정 | content_engine.py | publish_queue.csv |
| 검증 | 사람 | 발행 |

**남은 한계**
- 네이버 데이터라 구글 검색량과는 다릅니다. 다만 한국 트래픽 특성상 상관관계가 높습니다
- 경쟁도(compIdx)는 **광고 경쟁도**이지 SEO 경쟁도가 아닙니다. 광고가 적다고 유기적 상위노출이 쉬운 건 아니므로, 발행 전 실제 검색 확인은 여전히 필요합니다
- 다음 개선: 계산기 키워드군에 실제 JavaScript 계산기 삽입
