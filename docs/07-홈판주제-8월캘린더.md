# 07. 네이버 홈판 주제 후보 + 8월 이벤트 캘린더

## A. N 블로그(네이버) 홈판 주제 후보

홈판은 **주제 일관성**을 봅니다. 잡블로그는 추천 대상에서 빠집니다. 하나를 골라 8월 내내 고정합니다.

| 후보 | 홈판 적합도 | 애드센스 연결성 | 판단 |
|---|---|---|---|
| **생활정보·행정절차** (신청/발급/조회) | 상 | 상 (A 블로그 고단가와 직결) | **1순위** |
| 절약·재테크 생활 (전기요금, 통신비, 지원금) | 상 | 상 | 2순위 |
| 건강·의료 정보 | 상 | 중 (YMYL 제약) | 3순위 |
| 제품 비교·리뷰 | 중 | 상 (C 블로그 쿠팡 연결) | 4순위 |
| 시사 이슈 | 중 | 하 (언론사에 밀림) | 비추천 |

**1순위 근거:** 홈판은 "지금 당장 쓸모 있는 정보"에 강하고, 행정절차 글은 A 블로그의 고단가 키워드(대출·보험·세금·지원금)로 자연스럽게 이어집니다. 채널이 말한 "네이버 → 애드센스 연결 구조"와 정확히 맞습니다.

### 연결 규칙 (중요)

네이버 글도 그 자체로 완결이어야 합니다. 알맹이를 빼고 링크만 걸면 홈판에서 탈락하고 저품질로 갑니다.

- 네이버 글: 개요 + 핵심 절차 + 주의사항 (완결)
- 연결 글(티스토리): 상세 표, 계산 예시, 사례별 분기, 서식 다운로드 → **확장 정보**
- 링크는 본문 하단 "더 자세한 조건표 보기" 형태 1~2개

### 홈판 확률 요소 체크리스트

- [ ] 대표 이미지 1200px 이상 가로형, 텍스트 최소
- [ ] 첫 문단에 결론 (모바일 3줄 이내)
- [ ] 소제목 + 이미지 3~5장, 짧은 문단
- [ ] 발행 시간대 테스트 (07~09 / 12~13 / 18~20)
- [ ] 주제 카테고리 고정
- [ ] 발행 직후 초기 반응 확보

### 상시 감시 (엔진에 없는 것)

캘린더는 예측 가능한 것만 담습니다. 아래는 매일 아침 직접 확인해야 합니다.

- **정책브리핑 korea.kr** — 부처 보도자료. 발표 당일 아침이 골든타임
- **구글 트렌드 실시간 급상승**
- **네이버 뉴스 많이 본 뉴스**
- 돌발 이슈(사고·정전·서비스 장애·리콜) → `tools/issue_radar.py "이슈명" --type 사고`

돌발 이슈는 발생 후 **2시간 이내** 발행이 아니면 의미가 없습니다.

## C. 엔진 사용법

```bash
# 1회: 8/1~8/31 전체 큐 생성 (558편, 하루 18편)
python3 tools/content_engine.py queue

# 매일 아침: 오늘 쓸 18편
python3 tools/content_engine.py today

# 글 쓸 때: 구조 템플릿
python3 tools/content_engine.py brief "추석 기차표 예매 취소 방법"

# 돌발 이슈 발생 시
python3 tools/issue_radar.py "쿠팡 장애" --type 사고 --md
```

큐는 키워드 후보 **3,206개**에서 뽑은 558편이고, 잔여 2,648개는 9월 이월분입니다. **뭘 쓸지 고르는 단계가 없습니다** — 그날 목록을 위에서부터 쓰면 됩니다.

### 큐가 자동으로 지키는 것

- 이벤트별 슬롯 예약 (우선순위 10 → 12편) — 시즌물이 점수 경쟁에 밀려 누락되지 않음
- 선점일 이전에는 배정 안 됨, 이벤트일에 가까울수록 우선순위 상승
- 하루 목록이 한 축·한 시드로 쏠리지 않게 분산
- 유형에 안 맞는 조합 차단 ("안마의자 세금", "층간소음 무료 중계" 같은 것)
- 블로그별 슬롯 고정 (N3 / A3 / B7 / C3 / D2)

### 여전히 사람이 해야 하는 것

엔진은 **후보 생성기**지 검증기가 아닙니다. 발행 전 30초 확인은 반드시:

1. 네이버·구글에 그 키워드를 직접 검색
2. 상위 10개에 블로그 글이 3개 미만인가 → 예면 진행, 아니면 스킵하고 다음 것
3. 검색량이 아예 없는 조합은 버림

이 확인을 건너뛰면 아무도 안 찾는 키워드로 500편을 쓰게 됩니다.
